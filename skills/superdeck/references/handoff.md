# Handoff

Used in Phase 3: choosing the tool and building (3.1–3.2), reviewing the result (3.3) and the presenter kit (3.4).

## Options

Ask how the user wants to build the deck, showing only the options available in the session, with a recommendation.

**1. Claude's Slides** (when the session offers this artifact type)
- An editable deck inside Claude, with a link to share; exports to .pptx and PDF.
- Recommend it as the default when there is no mandatory corporate template.

**2. .pptx file** (PowerPoint skill)
- For when a corporate template must be used, the file must be delivered to the client, or it will be edited in PowerPoint.
- If the user has a .pptx template, ask for the file before building.

**3. Google Slides**
- If there is a Google Drive connector with permission to create files, create it there.
- If there isn't, offer a .pptx, which Google Slides opens normally.

**4. Prompt for an external tool** (Gamma, Canva, another slide AI)
- Generate a complete, self-contained prompt from the Production plan: context, audience, global rules and, slide by slide, title, visual, data and text.
- Warn that chart data must be checked afterwards, because external tools often alter it.

**5. Build checklist to assemble by hand**
- Deliver the Production plan formatted as a checklist, slide by slide, ready for the user to follow in the program they prefer.

## Building
- The Production plan is the specification, already decided with the user. Don't rewrite titles, add slides, swap visuals or invent data. If something isn't possible in the chosen tool, ask before adapting.
- Pass everything that was decided on to the build: global rules, identity, the content of each slide and the speaker notes.

## Review
Before delivering:
- **Against the Production plan:** every slide present, exact titles, correct data, highlight in the right place.
- **On the rendered deck** — images or a preview of the slides, not only the code or text: text cut off, overflowing or overlapping; a title longer than two lines; type too small for the format (live: legible from the back of the room); weak contrast; a chart highlighting the wrong figure or missing source and period; the same color meaning different things; a slide that breaks the visual concept.
- Fix what is only appearance; for anything that changes content, ask first.
- Tell the user what was fixed and what still diverges from the plan.

If the chosen tool doesn't let you see the result (a prompt for an external tool, a build checklist), deliver this review as a checklist for the user to run after assembling.

## Presenter kit
- **Anticipated Q&A:** the objections from the grill and the cold reader, each with a short answer and the slide or appendix item that supports it.
- **Backup slides** in the appendix for the most likely questions that don't fit in the main flow.
- **Short version:** the slides marked with `*` and what to say in the transition between them.
- **Talk track** with timing per block, if the user wants it.

Deliver what fits in the deck's own notes and appendix, and the rest in a short document.

## After delivery
Adjustments requested after the build that change content (not just appearance) must also be recorded in the Script and the Production plan, so they remain the source of truth.
