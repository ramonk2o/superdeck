# Handoff

Used in Deliver, after the checks. The text is finished; what is left is getting it where it will be read in a form the user can still edit.

## Choosing how to deliver

1. **Look at what this session can do right now** to deliver a text: editable document artifacts, skills that build document files, connectors to apps where the text will live (a document editor, a wiki, an email client), and plain text in the reply. Offer only what is actually available; never assume a tool exists.
2. **Judge each option against this text,** using what the Text plan says about the occasion: where it will be read or published, who edits it afterwards, and whether formatting has to survive the trip.
3. **Present two to four viable options,** numbered, each with one pro and one con for this text, and recommend one with the reason. In the light path, one line per option. The text in the reply, ready to copy, always exists as a fallback.

## Delivering
- The Text plan is the specification, as "A gate is explicit approval" in `SKILL.md` says: moving the text to another format doesn't reword it.
- An email goes as a draft, never sent: sending is the user's act.
